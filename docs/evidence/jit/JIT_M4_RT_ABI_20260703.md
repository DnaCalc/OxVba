# JIT M4-2 Runtime ABI Evidence

Date: 2026-07-03

Scope: `bd-h4oh.3` / `M4-2` shared runtime ABI substrate.

## Landed

- Added `crates/oxvba-rt-abi`, with no Cranelift dependency, as the shared runtime substrate below both `oxvba-vm3` and `oxvba-jit`.
- Extracted VM-agnostic runtime state into `ExecState`: loaded program tables, `ErrEngine`, event fabric, `LibContext`, host reference, allocation counter, ProcInvoker bridge, and drain guard.
- Extracted `ErrEngine` cells and decisions from vm3: per-activation save/restore, `On Error` policy updates, pending fault seating, fault dispatch, `Resume` target selection, `Err` clear/number, and `LastDllError`.
- Moved shared event fabric and loaded-program table shapes into `oxvba-rt-abi`; VM3 now owns only interpreter dispatch state such as frames, `For Each`, ParamArray aliases, and `As New` slots.
- Added the `ProcInvoker` seam plus a VM3 adapter over `run_proc_with_values` / callback invocation. Host/event ingress and the ABI drain bridge now cross the same invocation boundary.
- Added `docs/spec/JIT_V2_RUN_PROTOCOL_V1.md`, fixing shared link, initializer, entry, drain, and halt sequencing for VM3 and the future JIT driver.
- Extracted shared marshalling/copy-out helpers for `OxArg`/`OxCallArg`, optional COM ByRef writebacks, native-call argument collection, and `VariantChanged` copy-out guards.
- Extracted termination-batch resolution and cleanup helpers into the ABI layer; VM3 and `rt_maybe_drain` share the same pending-termination resolver.
- Added public typed kernels in `oxvba-eval::typed` for checked integer operations, narrowing, currency scaled-i128 arithmetic, currency rounding, and f64 arithmetic.
- Repointed existing Variant arithmetic facades to the typed kernels; property tests now compare typed and Variant facades over the same checked integer and currency kernels.
- Added shim surface v1 in `oxvba-rt-abi`: checked `i32` arithmetic, currency arithmetic, Variant arithmetic, Variant clone/release, type-specific null-safe releases, `rt_lib_invoke`, `rt_maybe_drain`, ProcInvoker install/clear, and Err/fault routing shims.

## Compatibility Boundaries

- `ExecState` is explicitly VM-agnostic session state. Interpreter frame mechanics, GoSub stacks, slot maps, and dispatch remain VM3-owned.
- `rt_maybe_drain` requires an installed ProcInvoker only when pending terminations exist; an empty queue remains a no-op.
- The M4-2 shim surface is the first static ABI slice. Cranelift lowering, dynamic entries, and ratchet-backed JIT execution remain M4-3+ work.
