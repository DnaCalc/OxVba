# DIV-0005: Internal Class Lifetime Teardown Does Not Yet Reliably Trigger `Class_Terminate`

- Scope impact: PMR/class lifecycle semantics, object-lifetime-sensitive event
  behavior, and value-model migration interface/lifetime work.
- Fixture:
  - `conformance/tests/class_lifecycle_terminate_fail.bas`
  - `crates/oxvba-host/src/engine.rs`
  - `crates/oxvba-build/src/comserver.rs`
  - `crates/oxvba-compiler/src/project.rs`
- Reproduction command:
  - `cargo test -p oxvba-host formal_v54_class_terminate_runs_after_main -- --nocapture`
  - `./scripts/run-conformance.ps1 -Backend vm -IncludePattern class_lifecycle_terminate_fail.bas`
  - Excel oracle evidence:
    `docs/evidence/conformance/oracle_captures/conformance_oracle_20260321T094401Z/summary.md`
- Observed OxVBA result:
  - OxVba already treats `Class_Initialize`/`Class_Terminate` as normative
    lifecycle hooks in spec/workset docs.
  - Internal class creation does explicitly invoke `Class_Initialize` in
    `Engine::create_class_instance`.
  - Compiler lowering injects `WithEvents` owner cleanup into explicit
    `Class_Terminate` bodies, so teardown work is prepared if
    `Class_Terminate` actually runs.
  - The current native internal-class runtime still does not show a general
    last-reference/scope-exit trigger that reliably invokes
    `Class_Terminate` for ordinary OxVba class instances.
  - The COM server scaffold also still contains an explicit future note on
    final `Release`: `Future: trigger Class_Terminate here before deallocation`.
  - The captured Excel oracle shows `class_lifecycle_terminate_fail.bas`
    succeeds with output `1`, while old OxVba's golden result is an error.
- Office VBA expected behavior:
  - `Class_Terminate` is part of the observable object-lifetime contract and
    runs on deterministic teardown/final-release paths.
- Tracking status:
  - Open bug against old OxVba, not an allowed alternative interpretation.
  - This divergence should be treated as a real baseline bug whenever old/new
    results differ on teardown-sensitive object semantics.
  - For value-model migration lane `vmm-f*`, retained COM identity/lifetime
    work should be anchored on `IUnknown`, with token-only `ObjectHandle`
    replaced by canonical `ObjectRef`.
