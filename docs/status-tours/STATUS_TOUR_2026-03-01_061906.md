## 3) End-to-end pipeline tour (source -> parser -> IL/bytecode -> VM/JIT)

### Source example

`conformance/tests/array_multidim_indexing.bas`

```vb
Sub Main()
Dim m(1 To 2, 1 To 3)
Dim x
m(2, 3) = 17
x = m(2, 3)
End Sub
```

### Syntax layer (green/red structures currently in place)

`crates/oxvba-syntax/src/green.rs`:

```rust
pub struct GreenNode {
    pub width: usize,
    pub children: Vec<String>,
}
```

`crates/oxvba-syntax/src/red.rs`:

```rust
pub struct RedNode<'a> {
    pub green: &'a GreenNode,
    pub absolute_offset: usize,
}
```

`crates/oxvba-syntax/src/parser.rs` currently does token-based source capture and roundtrip:

```rust
pub fn parse(source: &str) -> Result<SyntaxTree, ParseError> {
    let tokens = lexer::tokenize(source);
    let root = GreenNode::from_tokens(tokens.iter().map(|t| t.text.as_str()));
    Ok(SyntaxTree { source: source.to_string(), root })
}
```

This is intentionally lightweight today; it is enough for current lowering and formal roundtrip checks.

### Compiler pipeline

`crates/oxvba-compiler/src/lib.rs`:

```rust
let bound = resolve::resolve_symbols(source);
let checked = typecheck::check_types(bound)?;
let optimized = optimize::optimize_module(checked);
let _hir = lower_to_hir::lower_to_hir(&optimized);
emit::emit_bytecode(&optimized)
```

The compile test `compile_dim_assign_and_add` demonstrates emitted bytecode shape:

```rust
assert_eq!(
    out.instructions,
    vec![
        Instruction::LoadConstI32 { slot: 0, value: 10 },
        Instruction::AddConstI32 { slot: 0, value: 5 },
        Instruction::Halt
    ]
);
```

### IL / instruction surface

`crates/oxvba-compiler/src/bytecode.rs` includes:

- arithmetic ops (`LoadConstI32`, `AddConstI32`, `AddSlots`, ...)
- control flow ops (`JumpIfZero`, `Jump`, `CallProc`, `Return`, `Halt`)
- runtime intrinsic op families:
  - string/date/math/financial
  - array/type introspection
  - host/dispatch intrinsics
  - error mode and resume operations

So yes, there is an IL-like bytecode layer in place, and it executes now.

### VM execution

`crates/oxvba-vm/src/interpreter.rs` runs a `match` over bytecode instructions and mutates register slots:

```rust
match &bytecode.instructions[pc] {
    Instruction::LoadConstI32 { slot, value } => { ... }
    Instruction::AddConstI32 { slot, value } => { ... }
    Instruction::IntrinsicDateSerialDigits { ... } => { ... }
    Instruction::SetOnErrorResumeNext => { ... }
    ...
}
```

Snapshot visibility today is explicit via CLI:

```powershell
cargo run -q -p oxvba-cli -- run <file.bas> --dump-slots
# SLOTS:...
```

### JIT execution

`crates/oxvba-jit/src/lib.rs`:

```rust
if cranelift::supports_bytecode(bytecode) {
    return cranelift::execute_bytecode(bytecode);
}
execute_and_snapshot(bytecode) // VM fallback
```

`crates/oxvba-jit/src/cranelift.rs` defines the supported core subset and compiles those instructions with Cranelift.

This means:

- you can run via `--jit` today
- supported subsets execute in Cranelift
- unsupported instructions are still executable via fallback, preserving behavior
