## 3) The compiler binding model is now structured

From `crates/oxvba-compiler/src/resolve.rs`:

```rust
pub enum BoundExpr {
    IntConst(i32),
    Var(String),
    AddConst { var: String, delta: i32 },
    SubConst { var: String, delta: i32 },
}

pub enum BoundStmt {
    Assign { target: String, expr: BoundExpr },
    IfEq { lhs: BoundExpr, rhs: BoundExpr, then_body: Vec<BoundStmt> },
    ForRange { var: String, start: BoundExpr, end: BoundExpr, body: Vec<BoundStmt> },
    Unsupported { line: String },
}
```

Why it matters:
- Previous flat line-op model could not represent nested control flow safely.
- New model enables jump lowering and recursion over statement blocks.

## 4) Bytecode/IL is now control-flow capable

From `crates/oxvba-compiler/src/bytecode.rs`:

```rust
pub enum Instruction {
    LoadConstI32 { slot: usize, value: i32 },
    AddConstI32 { slot: usize, value: i32 },
    SubConstI32 { slot: usize, value: i32 },
    CopySlot { dst: usize, src: usize },
    CmpEqSlots { dst: usize, lhs: usize, rhs: usize },
    CmpLeSlots { dst: usize, lhs: usize, rhs: usize },
    JumpIfZero { cond_slot: usize, target_pc: usize },
    Jump { target_pc: usize },
    IncSlot { slot: usize },
    Halt,
}
```

`Bytecode` slot accounting now distinguishes:
- `slot_count`: total runtime slots (includes temporaries).
- `user_slot_count`: user-visible declared slots (used for snapshots).

## 5) VM execution is now `pc`-driven

From `crates/oxvba-vm/src/interpreter.rs`:

```rust
while pc < bytecode.instructions.len() {
    match &bytecode.instructions[pc] {
        Instruction::JumpIfZero { cond_slot, target_pc } => { ... }
        Instruction::Jump { target_pc } => { ... }
        ...
    }
}
```

New VM tests cover:
- branch + loop sequence,
- invalid jump target rejection,
- arithmetic compatibility with previous behavior.
