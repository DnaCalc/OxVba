# WORKSET: Phase 7 — DLL/EXE/COM Server Wrapper Builder

**Date:** 2026-03-23
**Phase:** 7
**Status:** Planned
**Depends on:** Phase 4 (native export mechanism), Phase 5 (Engine::invoke_procedure)

---

## Objective

Create the `oxvba-build` crate that generates standalone `.exe`, native `.dll`/`.so` wrappers with C ABI exports, and **COM server DLLs** (ActiveX DLLs) containing an embedded OxVba runtime + compiled `.oxb` bundle. COM server DLLs expose class modules as COM coclasses with `IDispatch` support, matching VB6 ActiveX DLL behavior.

### 1. New `crates/oxvba-build/` crate

### 3. DLL shim template

For each `NativeExport`:

```rust
static BUNDLE: &[u8] = include_bytes!("embedded.oxb");
static ENGINE: LazyLock<Mutex<(Engine, ProjectRuntimeSession)>> = LazyLock::new(|| { /* init */ });

#[no_mangle]
pub extern "system" fn CalcBlackScholes(arg0: f64, arg1: f64) -> f64 {
    let mut lock = ENGINE.lock().unwrap();
    let (engine, session) = &mut *lock;
    let args = vec![RuntimeValue::from(arg0), RuntimeValue::from(arg1)];
    let result = engine.invoke_procedure(session, "PricingFunctions", "BlackScholes", &args).unwrap();
    result.as_f64().unwrap()
}
```

### 4. Marshaling shim generation

Reuses `DeclareParamType` vocabulary in reverse:

| DeclareParamType | C param type | Unmarshal |
|-----------------|-------------|-----------|
| `Long` | `i32` | `RuntimeValue::I32(arg)` |
| `Double` | `f64` | `RuntimeValue::from_f64(arg)` |
| `String` | `*const u16` (BSTR) | `RuntimeValue::String(BStr::from_wide(arg))` |

Same mapping in reverse for return values.

### 6. COM server DLL shim (`OutputType=ComServer`)

The VB6 ActiveX DLL equivalent:

- **Standard COM exports**: `DllGetClassObject`, `DllCanUnloadNow`, `DllRegisterServer`, `DllUnregisterServer`
- **`IClassFactory` per creatable class**: Allocates a new VBA class instance via `Engine::create_class_instance`, wraps it in an `IDispatch` implementation
- **`IDispatch` implementation per class**: Routes `QueryInterface`, `AddRef`, `Release`, `GetTypeInfoCount`, `GetTypeInfo`, `GetIDsOfNames`, `Invoke` to the OxVba engine
  - `GetIDsOfNames` → maps member names to DISPIDs using `ProjectDynamicObjectRoute` member list
  - `Invoke` → calls `Engine::invoke_member_on_object` with marshaled `VARIANT` arguments
  - `VARIANT ↔ RuntimeValue` marshaling reuses existing COM client bridge patterns from `oxvba-com`
- **`DllRegisterServer`**: Writes CLSID, ProgId, InprocServer32, ThreadingModel=Apartment to registry
- **`DllUnregisterServer`**: Removes the above registry keys
- **Reference counting**: COM-standard `AddRef`/`Release` wrapping Rust `Arc` or manual ref count
- **STA enforcement**: Reject calls from non-STA apartments with `RPC_E_WRONG_THREAD`

### 7. Registry-free COM manifest generation (`.manifest` sxs file)

```xml
<?xml version="1.0" encoding="UTF-8" standalone="yes"?>
<assembly xmlns="urn:schemas-microsoft-com:asm.v1" manifestVersion="1.0">
  <file name="FinanceLib.dll">
    <comClass clsid="{...}" threadingModel="Apartment"
              progid="FinanceLib.Calculator" description="Calculator COM class" />
  </file>
  <typelib tlbid="{...}" version="1.0" helpdir="" />
</assembly>
```

This allows activation without registry entries (side-by-side deployment).

### 8. Type library (`.tlb`) generation

Emit a binary type library describing the COM server's coclasses and their IDispatch members. This enables early-bound access from COM clients. Implementation options:

- Generate IDL source and invoke MIDL compiler, OR
- Emit `.tlb` binary directly using `ICreateTypeLib2` COM API on Windows, OR
- Generate a portable metadata blob that can be converted to `.tlb` on Windows

**Phase 7 scope**: IDL generation + MIDL invocation (simplest). Direct `.tlb` emission deferred.

## Execution Steps

### C ABI DLL + EXE (OutputType=Library, Exe)

1. Create `oxvba-build` crate in workspace
2. Implement `generate_exe_shim` — template interpolation producing compilable Rust source
3. Implement `generate_dll_shim` — per-export `#[no_mangle] extern "system" fn` with type-correct C ABI signatures
4. Implement marshal/unmarshal code generation per `DeclareParamType` (13 type mappings × 2 directions)
5. Implement `.def` file generation for ordinal exports
6. Implement `compile_shim` — write generated source to temp dir, invoke `cargo build` or `rustc` targeting the appropriate output (cdylib for DLL, bin for EXE)

### COM Server DLL (OutputType=ComServer)

7. Implement `generate_com_server_shim` — generates Rust source with:
   - `DllGetClassObject` that matches CLSID to the correct `IClassFactory`
   - One `IClassFactory` vtable per creatable class (calls `Engine::create_class_instance`)
   - One `IDispatch` vtable per exposed class (routes to `Engine::invoke_member_on_object`)
   - `VARIANT ↔ RuntimeValue` marshaling using patterns from existing `oxvba-com` VARIANT handling
   - `DllCanUnloadNow` based on global reference count
8. Implement `generate_registration_code` — DllRegisterServer/DllUnregisterServer registry writes
9. Implement `generate_idl` — IDL source from `ComClassExportDescriptor` member inventories
10. Implement `generate_manifest` — side-by-side activation manifest XML
11. Integration tests:
    - C ABI DLL: generate shim for simple export, verify it compiles
    - COM server: generate shim for a class with 2 methods, verify it compiles and has correct exports

## Closure Conditions

1. `generate_exe_shim` produces compilable Rust source that embeds an .oxb and runs entry point
2. `generate_dll_shim` produces compilable Rust source with `#[no_mangle]` exports matching declared signatures
3. Marshal/unmarshal covers all 13 DeclareParamType variants
4. `.def` file correctly maps ordinals to export names
5. `generate_com_server_shim` produces compilable source with DllGetClassObject, IClassFactory, IDispatch
6. COM server shim correctly routes IDispatch::Invoke to Engine::invoke_member_on_object
7. Generated registration code writes/removes correct registry keys (CLSID, ProgId, InprocServer32)
8. Registry-free manifest XML is well-formed and contains correct CLSIDs
9. IDL output describes coclasses and their dispinterfaces
10. All generated shim sources compile without errors (verified by test)
