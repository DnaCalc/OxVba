## 1. Current HAL Snapshot

HAL is in place as a Rust trait boundary with:
- profile adapters (`windows`, `linux`, `macos`, `wasm`, `null`),
- policy presets (`strict-ci`, `deterministic-runtime`, `deterministic-compile-time`, `interactive-dev`),
- deterministic and host-backed execution modes,
- executable conformance harness with clause mapping to the HAL clause catalog.

### Profile/capability view (green/red style)

Legend: `G` = supported, `R` = unsupported (deterministic failure contract)

```
Windows (host-native):   UI G | Events G | FS G | Process G | COM G | Time G | DynLink G | Diag G
Linux (host-native):     UI G | Events G | FS G | Process G | COM R | Time G | DynLink G | Diag G
MacOs (host-native):     UI G | Events G | FS G | Process G | COM R | Time G | DynLink G | Diag G
Wasm (wasi/browser):     UI G*| Events G | FS R | Process R | COM R | Time G | DynLink R | Diag G
Null (null-floor):       UI R | Events R | FS R | Process R | COM R | Time G | DynLink R | Diag G
```

`UI G*` on Wasm is policy/virtualization-mode constrained.

## 4.2 Adapter implementation (where OS time is touched)
Source: `crates/oxvba-hal/src/adapters/standard.rs`

```rust
// lines 634-647
impl TimeLocaleHal for StandardHostServices {
    fn date_serial_now(&self) -> HalResult<i32> {
        let capability = CapabilityId::TimeLocale;
        if !self.supports(capability) {
            return Err(self.unsupported(capability, "date_serial_now"));
        }
        if self.native_time_enabled() {
            let now = SystemTime::now()
                .duration_since(UNIX_EPOCH)
                .unwrap_or_default();
            return Ok(clamp_u64_to_i32(now.as_secs() / 86_400));
        }
        Ok(20_260_301)
    }
```

```rust
// lines 649-675
fn time_serial_now(&self) -> HalResult<i32> { ... SystemTime::now() ...; Ok(1_234_56) }
fn timer_ticks(&self) -> HalResult<i32> { ... SystemTime::now() ...; Ok(42) }
```

Windows OS call boundary note:
- In host-backed mode, this uses Rust std time (`SystemTime::now`), which calls into OS time services.
- In deterministic mode, fixed tokens are returned for reproducibility.

## 4.5 Current VBA runtime integration status for `Now/Time/Date/Timer`

Current state:
- `Now/Time/Date/Timer` are classified as host-sensitive intrinsics.
- Compiler emits dedicated host instructions.
- VM executes them via `host.time_locale()` with stable HAL error routing.

Source: `crates/oxvba-compiler/src/resolve.rs`

```rust
// current shape
"date" | "time" | "now" | "timer" => HostSensitive
"freefile" => HostSensitive
...
"shell" | "environ" | "dir" | "createobject" => HostSensitive
"dispatchinvoke" => HostSensitive
```

Source: `crates/oxvba-compiler/src/emit.rs`

```rust
("date", []) => Instruction::IntrinsicDateNowHost { ... }
("time", []) => Instruction::IntrinsicTimeNowHost { ... }
("now", []) => Instruction::IntrinsicNowHost { ... }
("timer", []) => Instruction::IntrinsicTimerHost { ... }
("freefile", []) => Instruction::IntrinsicFreeFileHost { range_selector: None, ... }
("freefile", [range]) => Instruction::IntrinsicFreeFileHost { range_selector: Some(...), ... }
```

Source: `crates/oxvba-vm/src/interpreter.rs`

```rust
Instruction::IntrinsicDateNowHost { .. } => host.time_locale().date_serial_now()
Instruction::IntrinsicTimeNowHost { .. } => host.time_locale().time_serial_now()
Instruction::IntrinsicNowHost { .. } => host.time_locale().date_serial_now() // date projection in current token model
Instruction::IntrinsicTimerHost { .. } => host.time_locale().timer_ticks()
Instruction::IntrinsicFreeFileHost { .. } => host.fs().free_file(...)
```

Source: `crates/oxvba-host/src/engine.rs`

```rust
Instruction::IntrinsicDateNowHost { .. } => CapabilityId::TimeLocale
Instruction::IntrinsicTimeNowHost { .. } => CapabilityId::TimeLocale
Instruction::IntrinsicNowHost { .. } => CapabilityId::TimeLocale
Instruction::IntrinsicTimerHost { .. } => CapabilityId::TimeLocale
Instruction::IntrinsicFreeFileHost { .. } => CapabilityId::FileSystemIo
```

So the complete “VBA runtime -> HAL time -> OS time” lane is now implemented.

## 6. What Is Done vs What Is Next (for Time HAL specifically)

- conformance probes and clause checks for time,

Next:
- define richer token semantics for `Now` (true combined date-time token instead of date projection),
- extend host-sensitive wiring for broader file APIs and other HAL-adjacent runtime/library surfaces,
- add clause-level integration evidence linking engine tests to HAL clause IDs.
